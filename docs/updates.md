# 更新履歴

利用者向けの履歴は `src/content/updates.ts` の `UPDATES` に新しい順で置く。同じ日付の変更は1項目にまとめ、重複する内容は要約する。同日分を統合するときは、その日の最新IDを残す。新たな更新を追記するときはIDを新しくして新着を通知する。

- 通常の改善は `changes` に利用者向けの文で書く。開発専用の変更は載せない。
- 改善の説明でもシーンのネタバレを避ける。登場場所、具体的な仕草、登場する組み合わせなどは伏せ、「ドット絵」「表示位置」「タップ時の反応」など変更の種類だけを伝える。
- シーン追加は `addedScenes` に追加数だけを指定する。タイトル・内容・登場キャラクター・画像・出現条件は書かない。
- 今回の過去分は2026年9月7日以降のGit差分を対象に要約した。対象期間にシーン追加はない。

トップページの「更新履歴」に未読の最新更新があれば「新着」を表示する。初回も新着として扱い、履歴画面を開くと最新IDを既読にする。既読でも履歴はいつでも開ける。

既読は `localStorage` の `etokicchi:last-read-update` にID文字列として保存し、ゲームのセーブ形式は変更しない。保存が拒否された場合は訪問中のメモリに保持する。再読み込み後には再通知され得る。ブラウザ間・端末間では同期しない。新着の判定は読み込まれたアプリ内の履歴を使い、公開中の新バージョンを定期取得するものではない。

# 図鑑の時間帯操作

開くたびにゲーム内時計の現在の時間帯を選ぶ。デバッグ用の固定時刻にも追随する。閲覧中は時間の経過でタブを勝手に切り替えない。

図鑑の本文で左右に48px以上スワイプすると隣のタブへ移動する。順番は「すべて → 早朝 → 朝 → 昼 → 夕方 → 夜 → 深夜」で、両端では止まる。縦スクロール・ピンチズーム・拡大イラスト内の操作はタブ変更に使わない。

スワイプ・タブのタップによる切り替えは、移動方向に合わせて220msで横にスライドする。初期表示・同じタブの選び直し・端末の「視差効果を減らす」設定ではアニメーションを行わない。連続操作では前のアニメーションを片付け、最後の選択を優先する。

API確認: [MDN touch-action](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/touch-action)、[MDN localStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage)。
